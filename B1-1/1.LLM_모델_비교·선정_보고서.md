# LLM 모델 비교·선정 보고서

## 1. 비교 목적
기능 요구사항(회원가입) 기반 테스트 케이스 생성 어시스턴트 과업을 수행함에 있어, 서로 다른 3종의 대규모 언어 모델(LLM)인 GPT-5 mini, Gemini 3 Flash, Claude Haiku 4.5의 테스트 케이스 설계 능력, 프롬프트 준수율 및 명세 기반 사고 능력을 비교·평가하여 업무 자동화에 가장 적합한 최적의 모델을 선정하는 것을 목적으로 합니다.

---

## 2. 비교에 사용한 동일 입력 (테스트 프롬프트)

### [v1 프롬프트 (일반 지시)]
```jsx
아래 기능 요구사항을 분석하여 테스트 케이스를 생성해줘.
기능명: 회원가입

요구사항:
- 이메일 필수
- 이메일 중복 불가
- 비밀번호 8~20자
- 닉네임 2~10자
```

### [v1.5 프롬프트 (단계적 접근 및 작성 규칙 지정)]
```jsx
당신은 백엔드 QA 테스트 설계 전문가다.

아래 기능 요구사항을 분석하여 테스트 케이스를 생성한다.

작성 규칙:
1. 요구사항에 명시된 내용은 테스트 케이스로 작성한다.
2. 요구사항에 없지만 테스트에 영향을 주는 정책은 임의로 확정하지 말고 "확인 필요 사항"으로 분리한다.
3. 테스트 케이스는 정상 케이스, 예외 케이스, 경계값 테스트, 데이터 정합성 테스트, 보안/권한 테스트로 분류한다.
4. 각 테스트 케이스는 TC-ID, 분류, 시나리오, 전제조건, 입력값, 예상 결과, 우선순위 형식으로 작성한다.
5. 비밀번호 8~20자, 닉네임 2~10자처럼 범위 조건이 있으면 최소값-1, 최소값, 최대값, 최대값+1을 반드시 포함한다.
6. 이메일 중복처럼 데이터 정합성과 관련된 요구사항은 중복 데이터, 동시 요청 가능성을 고려한다.
7. 최종 출력에는 불필요한 칭찬, 설명, 감탄문을 포함하지 않는다.

기능명: 회원가입

요구사항:
- 이메일 필수
- 이메일 중복 불가
- 비밀번호 8~20자
- 닉네임 2~10자
```

## 4. 모델별 결과 요약 및 특징 분석

### 4.1 모델별 특징
* **GPT-5 mini**
  * **장점**: 요구사항 기반 경계값 분석이 완전하고 예외 상황 고려가 훌륭하며 동시성까지 포함됨. 명세 기반 사고 및 정책 추정이 최소화되어 있으며 확인 필요 사항 분리가 우수하고 정합성 관점이 강함.
  * **단점**: 과도하게 상세하여 요구사항 밖의 테스트가 많으며, 일부 케이스는 API 설계 리뷰 수준으로 확장됨 (예: Rate Limit, CAPTCHA, 요청 크기 제한 등 회원가입 기능 범위를 일부 넘어섬).
* **Gemini Flash**
  * **장점**: 가장 간결하며 실무에서 바로 사용할 수 있는 형태를 띠고 보안 테스트를 포함함.
  * **단점**: 경계값 성공 케이스(8자, 20자, 2자, 10자) 누락이 발생함. HTTP 상태코드, 해시 저장 여부, 이메일 형식 미검증 정책 등을 독자적으로 확정하여 QA 관점보다 개발자 관점의 가정이 많음.
* **Claude Haiku 4.5**
  * **장점**: 테스트 분류가 깔끔하고 BVA(경계값 분석) 적용이 우수하며 정합성 및 보안 테스트가 충실함.
  * **단점**: 실제 입력 데이터가 부족하고 실무성 있는 예외 상황이 부족함. 요구사항에 없는 이메일 형식 오류 메시지(TC-013)나 비밀번호 암호화 저장(TC-018), SQL Injection(TC-019), XSS(TC-020) 등 요구사항 외 정책 가정을 사실상 확정하여 프롬프트 규칙 위반이 가장 많은 편임.

### 4.2 요구사항 기준 커버리지 비교
| 요구사항 | GPT-5 mini | Gemini Flash | Claude Haiku 4.5 |
| --- | --- | --- | --- |
| 이메일 필수 | 100% | 100% | 100% |
| 이메일 중복 불가 | 150% (중복, 대소문자, 동시성) | 100% | 100% |
| 비밀번호 8~20자 | 100% | 50% | 100% |
| ### 4.3 최종 v2 프롬프트 적용 결과 비교 (Few-shot 및 검증 전략 추가 후)

Few-shot 예시 3종과 환각 방지 검증 전략이 추가된 최종 v2 프롬프트의 모델별 실행 결과는 다음과 같습니다.

* **Gemini Flash & Claude Haiku 4.5 (환각 통제 성공)**
  * **분석**: 이전 v1.5 버전에서 자의적으로 HTTP 상태코드(201, 400 등)와 암호화 방식을 결정하던 환각 현상이 완벽하게 통제되었습니다.
  * **수치/규격**: 두 모델 모두 명세 외 비지정 항목들을 **`[확인 필요] 사후 정책 결정에 따름`** 플레이스홀더로 치환하며 규격을 100% 준수하였으며, 경계값 8개 및 보안/권한 13개 케이스를 안정적으로 구조화하였습니다.
* **GPT-5 mini (디테일 유지)**
  * **분석**: 이전 버전의 풍부한 상세 케이스 도출 성향을 그대로 유지하면서, 작성 규칙과 검증 전략에 부합하게 동작하였습니다.
  * **수치/규격**: 이메일 유효성, 비밀번호 복잡성 등 **총 13가지의 확인 필요 사항**을 정밀하게 추출해 냈으며, `SIGNUP-001`부터 경계값 `SIGNUP-BND-008` 및 암호화 저장 검증을 포함한 `SIGNUP-013` 보안 케이스까지 가장 완벽한 QA 적합성을 보여주었습니다.
* **종합 결론**: 최종 v2 프롬프트에 도입된 Few-shot 예시와 환각 방지 지침이 세 모델 모두에 강력하게 작용하여 환각율 0%를 달성하였으며, 테스트 케이스의 정량적 완성도와 미지정 정책 발굴 수준에서 GPT-5 mini가 최상위에 해당하였습니다.

## 5. 최종 선정 결론
v1.5 및 최종 v2 프롬프트 적용 결과, 세 모델 모두 v1에 비해 출력 형식 준수율과 테스트 분류 품질이 크게 개선되었습니다. 특히 최종 v2 프롬프트에서는 Few-shot 예시와 환각 방지 검증 전략이 적용되어, 이전 버전(v1.5)에서 발생하던 Gemini Flash와 Claude Haiku 4.5의 HTTP 상태코드 및 암호화 방식 임의 확정(환각) 오류가 100% 차단되었습니다. 세 모델 모두 미지정 정책 영역에 대해 `[확인 필요]` 플레이스홀더를 적용하며 명세 기반 테스트 설계 규칙을 성실히 준수하였습니다. 다만, 확인 필요 사항 식별 깊이와 엣지 케이스 도출 수준에서 가장 세밀하고 뛰어난 완성도를 보여준 **GPT-5 mini**를 최종 업무 자동화 모델로 선정합니다.
