# 검증 계획

## 1. 목적

이 문서는 결과물이 우연히 한 번 실행된 상태가 아니라, 원자료부터 다시 만들 수 있고 분석 수치가 정해진 기준을 만족함을 확인하는 방법을 정의한다.

## 2. 검증 계층

### 2.1 단위 테스트

외부 네트워크 없이 작은 입력으로 개별 계산과 검증 함수를 확인한다.

### 2.2 통합 테스트

fixture ZIP과 CSV를 사용해 파일 발견, 중첩 ZIP 해제, 인코딩 처리, 통합 CSV 생성 흐름을 확인한다.

### 2.3 실제 데이터 검증

기상청에서 1994~2024년 자료를 내려받고 전체 데이터 품질을 검사한다.

### 2.4 산출물 검수

생성된 이미지와 REPORT 링크, 필수 섹션, 출처표시를 확인한다.

## 4. 실제 데이터 검증 기준

### 4.1 파일 수준

- 대상 연도 파일이 31개인지 확인한다.
- 각 연도 manifest 항목이 있는지 확인한다.
- 각 원본 파일의 SHA-256을 다시 계산해 manifest와 비교한다.
- 압축 해제된 CSV가 비어 있지 않은지 확인한다.

### 4.2 행 수준

- 데이터 포인트가 100개 이상인지 확인한다.
- 실제 시작일과 종료일을 확인한다.
- 고유 날짜 수와 전체 행 수를 비교한다.
- 11,323개 예상 달력 날짜와 비교해 누락 날짜를 계산한다.
- 지점번호가 모두 `108`인지 확인한다.
- 평균·최저·최고기온의 결측 건수와 비율을 계산한다.
- 최저·평균·최고기온 순서 위반 건수를 계산한다.

예상 달력 일수 11,323은 완전성 검증 기준이다. 원자료에 누락 날짜가 있는지는 검증 전까지 가정하지 않지만, 검증에서 하나라도 확인되면 분석을 중단한다. 월·연 관측률 기준은 날짜 행이 모두 존재하는 상태에서 변수별 결측치를 처리하기 위한 기준이다.

### 4.3 집계 수준

- 월평균에 80% 관측률 기준이 적용됐는지 확인한다.
- 연평균에 95% 관측률 기준이 적용됐는지 확인한다.
- 월별 집계가 1~12월 이외 값을 만들지 않는지 확인한다.
- 선형 추세 계산에 사용된 연도 수를 기록한다.
- 이상 고온·저온 후보의 원본 날짜와 기온을 역추적할 수 있는지 확인한다.

## 6. 전체 재현 검증

최종 완료 전에 새 Python 가상환경에서 다음 순서로 검증한다.

`download` 기본 실행은 실제 수집 경로까지 확인하는 추가 통합 검증이다. 자동 다운로드 없이 검증할 때는 보존 원자료의 `--rebuild-from-raw` 경로 또는 [수동 데이터 입력 지침](manual-data-input.md)에 맞춘 표준 CSV를 사용한다. 패키지 실행과 콘솔 실행을 각각 확인한다.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m seoul_weather run --rebuild-from-raw
seoul-weather run --rebuild-from-raw
python -m pytest
```

검증 결과에 다음을 기록한다.

- Python 버전
- 라이브러리 버전
- 실행일시
- 다운로드 성공 연도 수
- 가공 데이터 행 수와 기간
- 테스트 통과·실패 수
- 생성된 이미지 목록

## 7. 실패 판정

다음 중 하나라도 발생하면 완료로 보고하지 않는다.

- 원자료 연도가 누락됐는데 이유를 기록하지 않음
- 필수 컬럼이 없는데 분석을 계속함
- 충돌하는 중복 날짜를 임의로 선택함
- 핵심 결측치를 `0`으로 대체함
- 이미지 링크가 깨짐
- 테스트 실패가 남아 있음
- 관찰 근거 없는 인사이트가 있음
- 데이터 출처 또는 AI 사용 로그가 없음

## 8. 수동 검토가 필요한 항목

자동 테스트만으로 다음을 확정할 수 없으므로 사람이 확인한다.

- 그래프가 오해를 유발하지 않는지
- 주석이 실제 값을 정확히 가리키는지
- 관찰과 해석이 문장에서도 분리됐는지
- 장기 추세를 인과관계로 과장하지 않았는지
- 한계점이 결론의 강도와 일치하는지
- AI가 제안한 해석이 데이터로 뒷받침되는지

## 9. 실제 검증 결과

최종 패키지 구조 검증일은 2026-08-23이며 별도의 Python 3.10 임시 가상환경에서 수행했다.

| 항목 | 결과 |
| --- | --- |
| Python | 3.10.18 |
| 직접 의존성 | `requirements.txt`의 7개 고정 버전 |
| 패키지 설치 | `pip install -e .` 성공, `seoul-weather-analysis 0.1.0` |
| 실다운로드 | 31개 연도 성공 |
| 원본 manifest | 31개 항목, 파일 기록 93개 |
| 가공 CSV | 11,323행, 1994-01-01~2024-12-31 |
| 가공 CSV SHA-256 | `682793de38503fbf8d1d54c7421197f2128ccfce7ee4f9c8d365dc7dba6bd29f` |
| 날짜 완전성 | 누락 0, 중복 0 |
| 테스트 | 95개 통과, 실패 0 |
| 실행 진입점 | 패키지·콘솔의 `download`, `analyze`, `run` 성공 |
| 이미지 | 지정된 PNG 3개 생성·열기·육안 검수 완료 |
| GitHub 제출 준비 | 원본·가공 데이터·이미지가 Git 제외 대상이 아니며 전체 데이터 약 5.1MB, 커밋·push는 지침에 따라 미수행 |

검증한 순서:

```bash
python3.10 -m venv /tmp/m1-1-src-refactor-py310.8AVZ5W/venv
/tmp/m1-1-src-refactor-py310.8AVZ5W/venv/bin/python -m pip install -e .
/tmp/m1-1-src-refactor-py310.8AVZ5W/venv/bin/python -m seoul_weather download --rebuild-from-raw
/tmp/m1-1-src-refactor-py310.8AVZ5W/venv/bin/python -m seoul_weather analyze
/tmp/m1-1-src-refactor-py310.8AVZ5W/venv/bin/python -m seoul_weather run --rebuild-from-raw
/tmp/m1-1-src-refactor-py310.8AVZ5W/venv/bin/seoul-weather download --rebuild-from-raw
/tmp/m1-1-src-refactor-py310.8AVZ5W/venv/bin/seoul-weather analyze
/tmp/m1-1-src-refactor-py310.8AVZ5W/venv/bin/seoul-weather run --rebuild-from-raw
/tmp/m1-1-src-refactor-py310.8AVZ5W/venv/bin/python -m pytest -q
```

`run --rebuild-from-raw`는 기존 manifest의 93개 파일 크기와 SHA-256을 다시 검사하고 보존 CSV에서 31개 연도를 재통합한 뒤 분석까지 수행했다. 패키지 실행과 콘솔 실행의 가공 CSV SHA-256과 분석 통계가 같았다. 두 실행 방식 모두 11,323행, 선형 추세 `+0.302°C/10년`, R² `0.187`, 고온 후보 43일, 저온 후보 98일을 출력했다.

세 PNG는 직접 열어 한글, 축, 범례, 색상 범위와 주석을 확인했다. REPORT의 네 인사이트는 관찰·해석·한계·행동을 분리했으며 인과관계로 단정한 문장이 없는지 검토했다.
