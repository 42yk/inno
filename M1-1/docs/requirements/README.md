# 서울 장기 기온 분석 요구사항

## 1. 목적

기상청의 서울 일별 기상자료를 정제하고 시계열 분석하여 1994~2024년의 장기 기온 추세, 계절 패턴, 이상 기온을 근거와 함께 설명한다.

그래프를 만드는 데 그치지 않고 다음을 구분해 기록하는 것이 핵심이다.

- 관찰은 데이터와 그래프에서 직접 확인할 수 있는 사실과 패턴이다.
- 해석은 관찰이 무엇을 의미하는지 설명하는 판단이다.
- 가설은 관찰의 가능한 원인을 설명하며 추가 자료로 검증해야 하는 주장이다.
- 한계는 데이터만으로 확인할 수 없는 원인과 외부 변수다.

## 2. 분석 범위

### 포함 범위

- 서울 종관기상관측 지점 `108`
- 1994-01-01부터 2024-12-31까지의 일자료
- 평균기온, 최저기온, 최고기온 중심 분석
- 강수량과 상대습도는 데이터 품질 확인 및 보조 설명에 제한적으로 사용
- 결측치, 날짜 중복, 값 범위, 기온 순서 관계 검사
- 이동평균, 연도·월별 집계, 변화량, 이상 기온 분석
- PNG 시각화 3개 생성
- Markdown 분석 리포트 작성
- Python 스크립트와 자동 테스트 제공
- `src` 기반 Python 패키지와 콘솔 명령 제공

### 제외 범위

- 미래 기온 예측
- 시계열 분해 보너스 과제
- 웹 대시보드 및 서비스 배포
- 서울 외 지역과의 비교
- 날씨 현상의 원인을 단정하는 인과 분석
- 머신러닝 모델 학습

## 3. 분석 질문

다음 질문에 답할 수 있어야 한다.

1. 1994~2024년 서울의 연평균 기온은 어떤 방향과 크기로 변했는가?
2. 월별·계절별 기온 패턴은 어떻게 나타나며, 초기 10년과 최근 10년 사이에 차이가 있는가?
3. 같은 계절의 일반적인 범위에서 크게 벗어난 고온·저온 시기는 언제였는가?
4. 관찰된 변화와 이상 기온을 해석할 때 데이터만으로 말할 수 있는 범위와 말할 수 없는 범위는 무엇인가?

## 4. 기능 요구사항

### FR-001 원자료 수집

- 기상청 기상자료개방포털의 ASOS 연도별 파일셋을 사용한다.
- 서울 지점번호 `108`의 1994~2024년 일자료를 수집한다.
- 연도별 원본 파일과 수집 메타데이터를 보존한다.
- 수집일시, 대상 연도, 원본 파일명, 파일 해시를 기록한다.
- 특정 연도 수집 실패 시 전체 성공으로 처리하지 않고 실패 연도를 명확히 출력한다.

### FR-002 데이터 통합

- 중첩 ZIP을 풀고 CP949 CSV를 UTF-8로 읽는다.
- 31개 연도 파일을 날짜 기준으로 하나의 테이블로 통합한다.
- 원본 한글 컬럼을 분석용 영문 컬럼명으로 표준화한다.
- 처리 결과를 `data/processed/seoul_weather_daily.csv`로 저장한다.

### FR-003 데이터 기본 정보 확인

- 실제 시작일과 종료일을 출력한다.
- 전체 행 수와 고유 날짜 수를 출력한다.
- 컬럼별 자료형과 결측치 수·비율을 출력한다.
- 예상 달력과 비교해 누락 날짜가 하나라도 있으면 개수와 예시를 출력하고 분석을 중단한다.
- 중복 날짜를 확인한다.
- 서울 지점 `108` 이외의 행이 포함되지 않았는지 확인한다.

### FR-004 결측치 및 오류 처리

- 평균·최저·최고기온의 결측치는 임의의 값으로 대체하지 않는다.
- 결측 기온은 집계에서 제외하되 제외 건수와 비율을 리포트에 기록한다.
- 강수량 공백을 자동으로 `0`으로 바꾸지 않는다. 기상청 자료 정의로 무강수와 결측을 구분할 수 있을 때만 변환한다.
- 날짜 중복은 원자료 위치를 추적한 후 동일 행이면 하나만 유지하고, 값이 충돌하면 오류로 중단한다.
- `최저기온 <= 평균기온 <= 최고기온` 관계를 위반한 행은 의심 자료로 분류한다.
- 평균·최저·최고기온이 `-50°C` 미만 또는 `50°C` 초과인 행은 보수적 품질검사 후보로 기록한다.
- 물리적으로 의심되는 값은 자동 삭제하지 않고 원자료와 단위를 확인한 후 처리 근거를 기록한다.

### FR-005 시계열 분석

최소 다음 분석 기법을 적용한다.

1. 연평균 기온과 5년 이동평균
2. 연평균 기온의 전년 대비 변화량과 선형 추세
3. 월별·계절별 평균 집계
4. 같은 달의 [평년값](../learning/glossary.md#평년값-climatological-normal) 대비 일별 기온 편차와 표준화 편차

선형 추세는 `°C/10년` 단위로 제시하고, 선택한 31년 자료에서 관찰된 통계적 경향임을 명시한다.

### FR-006 시각화

다음 PNG 파일 3개를 생성한다.

1. `images/01_annual_temperature_trend.png`
   - 연평균 기온
   - 5년 이동평균
   - 선형 추세선
2. `images/02_monthly_temperature_heatmap.png`
   - 연도별·월별 평균기온 또는 [평년값](../learning/glossary.md#평년값-climatological-normal) 대비 편차
3. `images/03_temperature_anomalies.png`
   - 같은 달의 일반적인 분포에서 크게 벗어난 고온·저온 관측

모든 그래프는 제목, 축 이름, 단위, 범례와 데이터 기간을 포함해야 한다.

### FR-007 인사이트 작성

- 최소 3개의 인사이트를 작성한다.
- 각 인사이트에는 수치 또는 기간을 포함한 관찰을 먼저 쓴다.
- 관찰 다음에 가능한 해석을 별도로 쓴다.
- 외부 사건이나 기후 원인을 언급할 경우 해석과 섞지 않고 가설로 구분하며, 별도의 근거 자료가 없으면 가능성으로 표현한다.
- 각 인사이트에 추가 분석 또는 활용 방향을 한 가지 이상 제시한다.

### FR-008 분석 리포트

`REPORT.md`에 다음 항목을 포함한다.

1. 분석 주제 및 선정 이유
2. 분석 질문
3. 데이터 출처, 기간, 지점, 라이선스와 수집 방법
4. 데이터 기본 정보와 정제 기준
5. 적용한 시계열 분석 기법
6. 시각화 3개와 그래프별 설명
7. 관찰과 해석이 구분된 인사이트 3개 이상
8. 결론
9. 한계점
10. AI 사용 로그

### FR-009 AI 사용 로그

리포트에 다음 내용을 기록한다.

- AI를 사용한 작업
- AI를 사용한 이유
- AI가 생성하거나 제안한 결과를 검증한 방법
- 사람이 최종 판단한 내용

### FR-010 README 결과 안내

- 구현 전 README에 시각화, 인사이트와 리포트의 결과물 예시를 포함한다.
- 예시에는 실제 분석 결과가 아니라는 안내를 표시한다.
- 실제 분석과 검증이 완료되면 README에 데이터 수, 기간, 결측 현황, 핵심 통계와 인사이트를 반영한다.
- 생성된 시각화 3개를 README에서 직접 확인할 수 있게 한다.
- 최종 `REPORT.md` 링크를 제공한다.
- README의 수치는 분석 코드의 검증된 출력과 일치해야 한다.

### FR-011 실행 인터페이스

- 모든 Python 구현 코드는 `src/seoul_weather/` 패키지 아래에 둔다.
- 수집, 정규화, 분석, 시각화와 workflow를 책임별 모듈로 분리한다.
- `python -m seoul_weather` 패키지 실행과 `seoul-weather` 콘솔 실행을 모두 제공한다.
- `download`, `analyze`, `run` 하위 명령을 제공한다.
- `run`은 원자료 수집 또는 재통합 후 분석과 시각화를 순서대로 수행한다.
- 자동 다운로드는 선택적 편의 기능으로 유지하고, 표준 CSV를 직접 제공한 사용자는 `analyze`만 실행할 수 있어야 한다.

## 5. 비기능 요구사항

### NFR-001 재현성

- Python 3.10 이상에서 실행할 수 있어야 한다.
- `requirements.txt`에 직접 사용하는 라이브러리와 버전을 기록한다.
- 새로운 환경에서 문서화된 방법으로 데이터를 준비하고 분석과 이미지 생성을 다시 수행할 수 있어야 한다.
- 자동 다운로드는 필수 요구사항이 아니며, 표준 CSV를 직접 제공하는 입력 형식을 문서화한다.
- 동일한 입력 자료를 사용하면 핵심 통계와 이미지 파일이 같은 방식으로 생성되어야 한다.

### NFR-002 검증 가능성

- 데이터 검증과 분석 계산을 함수 단위로 분리한다.
- `pytest` 자동 테스트를 제공한다.
- 전체 실행이 실패하면 0이 아닌 종료 코드를 반환한다.
- 누락된 원자료·필수 컬럼·날짜를 경고만 하고 넘어가지 않는다.

### NFR-003 추적 가능성

- 가공 데이터의 각 컬럼을 원본 컬럼에 대응시킬 수 있어야 한다.
- 원본 파일은 수정하지 않는다.
- 삭제·대체·제외된 행의 수와 기준을 기록한다.
- 데이터 출처 URL과 접근일을 문서에 남긴다.

### NFR-004 표현 품질

- 그래프만 나열하지 않는다.
- 관찰과 해석을 명시적으로 구분한다.
- 상관관계를 인과관계로 표현하지 않는다.
- “서울의 기후 전체”가 아니라 “서울 지점 `108`의 선택 기간 자료”에 대한 결과임을 밝힌다.

### NFR-005 보안

- 공공데이터 API 키가 필요해지는 경우 코드나 저장소에 키를 기록하지 않는다.
- 현재 채택한 공개 파일셋 수집 방식은 인증정보를 요구하지 않아야 한다.

## 8. 변경 관리

이 문서에서 정한 범위를 변경하려면 변경 이유와 결과물에 미치는 영향을 먼저 기록한다. 특히 분석 기간, 관측 지점, 이상 기온 기준, 결측치 처리 방식의 변경은 기존 결과와 직접 비교할 수 없게 만들 수 있으므로 문서와 테스트를 함께 수정해야 한다.
