# 데이터 분석 개념 학습 가이드

이 문서는 서울 장기 기온 분석 프로젝트에 필요한 개념을 설명한다.

Python 문법이나 pandas 사용법은 중심 내용이 아니다. 각 개념의 필요성과 분석에서 맡는 역할에 초점을 둔다.

짧은 정의가 필요할 때는 [데이터 분석 용어집](glossary.md)을 참고한다. 이 문서는 용어를 외우는 사전이 아니라 개념 사이의 관계를 이해하는 해설서다.

## 1. 데이터 분석이 필요한 이유

데이터는 현실에서 측정하거나 수집한 값을 정리한 것이다. 이 프로젝트에서는 날짜별 기온, 강수량과 습도가 데이터에 해당한다.

값이 많이 모여 있어도 그 자체로는 질문의 답이 되지 않는다. 서울의 일별 기온 11,323개를 그대로 나열하면 장기 변화를 파악하기 어렵다.

데이터 분석은 값을 비교하고 요약해 질문의 답을 찾는 과정이다.

### 1.1 데이터에서 필요한 패턴을 찾는다

같은 기온 데이터에도 서로 다른 질문을 던질 수 있다.

| 질문 | 필요한 관점 |
| --- | --- |
| 장기적으로 기온이 변했는가? | 연평균과 선형 추세 |
| 매년 반복되는 특징이 있는가? | 월별·계절별 집계 |
| 평소보다 이례적인 날은 언제인가? | 같은 달의 분포와 z 점수 |

질문이 달라지면 분석 방법도 달라진다. 일별 기온은 짧은 날씨 변화를 보여 준다. 연평균은 장기 방향을 보여 준다. z 점수는 해당 달에서 드문 관측을 찾는 데 쓰인다.

### 1.2 잘못된 판단을 줄인다

값이나 그래프를 바로 해석하면 중요한 조건을 놓칠 수 있다. 날짜가 빠졌을 수 있다. 결측치를 `0`으로 처리했을 수도 있다. 계절 변화를 장기 상승으로 오해할 수도 있다.

그래서 계산 전에 데이터 품질을 확인한다. 출처와 기간을 확인한다. 날짜, 결측치, 중복과 값의 범위도 검사한다. 이 과정은 분석 결과가 어떤 데이터에서 나왔는지 분명하게 만든다.

### 1.3 근거와 설명을 구분한다

분석 결과는 관찰의 근거를 제공한다. 예를 들어 `+0.302°C/10년`이라는 기울기는 코드로 다시 계산할 수 있다.

상승 원인이 도시화라는 설명은 이 기온 데이터만으로 확인할 수 없다. 추가 자료가 필요한 가설이다.

데이터 분석은 숫자를 만드는 데서 끝나지 않는다. 데이터로 확인한 사실을 밝힌다. 확인할 수 없는 부분도 함께 밝힌다. 그래야 결론의 범위를 과장하지 않을 수 있다.

이 프로젝트의 분석 질문과 최종 해석은 [분석 리포트](../../REPORT.md)의 2절과 7절에서 확인할 수 있다.

## 2. 데이터 구조

### 2.1 데이터 포인트와 변수

데이터 포인트는 분석 대상이 되는 개별 관측 단위다. 이 프로젝트에서는 하루 기상 관측 한 행이 하나의 데이터 포인트다.

대상은 서울 ASOS 지점 `108`이다. 가공 데이터에는 1994-01-01부터 2024-12-31까지 11,323개의 데이터 포인트가 있다.

변수는 각 데이터 포인트에서 기록한 특성이다. 날짜, 평균기온, 최저기온, 최고기온, 강수량과 평균 상대습도가 변수에 해당한다.

행과 열을 구분하면 분석 질문의 단위가 명확해진다.

“가장 따뜻했던 해”를 찾을 때는 하루 단위 행을 연도별로 묶는다. “강수량이 비어 있는 날의 비율”을 구할 때는 강수량 변수의 결측 상태를 센다.

### 2.2 자료형

자료형은 값이 어떤 의미와 연산 규칙을 가지는지 정한다.

| 자료형 | 이 프로젝트의 예 | 필요한 이유 |
| --- | --- | --- |
| 날짜 | `date` | 시간순 정렬, 연·월 추출, 누락 날짜 검사 |
| 정수 | `station_id` | 서울 지점 `108` 검증 |
| 실수 | `avg_temp_c` | 평균, 편차, 추세 계산 |
| 문자열 | `station_name` | 사람이 읽을 수 있는 지점 표시 |
| 결측 가능 실수 | `precipitation_mm` | 숫자와 빈값을 구분해 보존 |

숫자처럼 보이는 문자열도 바로 계산할 수는 없다. 잘못된 날짜 문자열은 시간순으로 정렬할 수 없다.

정제 단계에서는 값을 날짜와 숫자로 변환한다. 비어 있지 않은 값을 변환하지 못하면 오류로 중단한다. 이를 결측치로 바꾸면 원래 오류가 단순한 빈값으로 숨겨지기 때문이다.

### 2.3 시계열 데이터와 시간 축

시계열 데이터는 시간 순서가 의미를 가지는 데이터다. 같은 기온 목록이라도 날짜 순서가 사라지면 상승 추세, 계절 반복, 갑작스러운 변화와 연속된 이상 현상을 알 수 없다.

시계열을 분석하기 전에는 다음을 확인해야 한다.

- 날짜가 실제 날짜 자료형인가?
- 날짜가 오름차순으로 정렬됐는가?
- 같은 날짜가 중복됐는가?
- 분석 기간에서 날짜 행이 빠졌는가?
- 관측 간격이 일 단위로 일정한가?

전체 행과 고유 날짜는 모두 11,323개다. 분석 기간의 달력과 비교해도 빠진 날짜가 없다.

따라서 일정한 일 간격으로 시간 집계를 적용할 수 있다.

### 2.4 원자료와 가공 데이터

원자료는 제공기관에서 받은 내용을 변경하지 않은 파일이다.

가공 데이터는 분석에 필요한 열만 남긴 결과다. 열 이름과 자료형도 표준화한다. 여러 연도의 파일은 하나로 합친다.

두 데이터를 구분하면 잘못된 변환을 추적할 수 있다. 가공 값이 의심스러울 때 원자료와 비교할 수도 있다.

정제 방식이 바뀌면 원자료에서 다시 시작한다. 이 프로젝트는 연도별 ZIP과 CP949 CSV를 그대로 보존한다. UTF-8 표준 CSV는 별도 경로에 생성한다.

구체적인 컬럼 대응 관계는 [데이터 출처와 수집 정책](../design/data-source.md)의 6절에서 확인할 수 있다.

## 3. 데이터 품질

분석 결과는 입력 데이터의 상태에 큰 영향을 받는다. 계산 방법이 정확해도 데이터가 잘못되면 결과를 믿기 어렵다.

데이터 품질 확인은 결함의 종류와 영향을 판단하는 과정이다. “값이 많으니 괜찮다”라고 가정하지 않는다.

### 3.1 결측치, `0`, 누락 날짜

결측치는 값이 기록돼 있지 않은 상태다. 결측치는 숫자 `0`과 다르다. `0°C`는 실제 기온이지만 기온 빈칸은 관측값을 알 수 없다는 뜻이다. 강수량도 `0mm`와 빈칸의 의미가 다를 수 있다.

누락 날짜는 값 하나가 비어 있는 것이 아니라 날짜 행 전체가 없는 상태다. 두 경우는 분석에 미치는 영향도 다르다.

| 상태 | 예 | 의미 | 처리 방향 |
| --- | --- | --- | --- |
| 관측값 `0` | 평균기온 `0°C` | 실제로 관측된 값 | 분석에 포함 |
| 결측치 | 최고기온 빈칸 | 해당 변수의 값을 알 수 없음 | 임의 대체하지 않고 집계에서 제외 |
| 누락 날짜 | 2020-01-02 행 없음 | 그날의 관측 행 자체가 없음 | 개수와 예시를 확인하고 분석 중단 |

이 프로젝트의 실제 품질 결과는 다음과 같다.

- 평균기온 결측: 0건
- 최저기온 결측: 1건
- 최고기온 결측: 1건
- 강수량 공백: 6,940건, 전체의 61.29%
- 누락 날짜: 0일

평균기온에는 결측이 없다. 따라서 연평균과 월평균에서 제외된 날짜도 없다.

강수량 공백은 현재 파일만으로 무강수와 미관측을 구분할 수 없다. 그래서 `0`으로 바꾸지 않았다. 강수량 평균과 기온의 관계도 분석하지 않았다.

결측치를 발견해도 바로 채우지 않는다. 먼저 “왜 비었는가?”를 확인한다. “빈값이 분석 질문에 어떤 영향을 주는가?”도 확인해야 한다.

### 3.2 중복 데이터와 충돌 데이터

중복 데이터는 같은 관측 단위가 둘 이상 기록된 상태다. 같은 날짜와 같은 값이 완전히 반복됐다면 하나를 제거할 수 있다. 그러나 같은 날짜의 값이 서로 다르면 단순 중복이 아니라 충돌이다.

충돌하는 행 중 하나를 임의로 고르면 버려진 값을 추적하기 어렵다. 결과도 재현하기 어렵다.

이 프로젝트는 완전히 같은 중복만 하나로 합친다. 이때 원본 위치를 기록한다. 같은 날짜의 값이 다르면 분석을 중단한다. 실제 자료의 중복 날짜는 0건이었다.

### 3.3 이상치, 오류 데이터, 이상 기온

이 세 개념은 같은 기준으로 나눈 종류가 아니다. 서로 다른 질문에 답한다.

이상치는 값이 분포에서 얼마나 떨어져 있는지를 설명한다. 오류 데이터는 값이 믿을 만한지를 판단한 결과다. 이상 기온은 품질검사를 통과한 실제 기온이 평소와 크게 다른 현상이다.

| 개념 | 의미 | 판정 근거 | 분석 관점 |
| --- | --- | --- | --- |
| 이상치 | 다른 값들과 비교해 분포에서 멀리 떨어진 값 | IQR, z 점수 등 통계 기준 | 원인을 조사하며 자동으로 삭제하지 않음 |
| 오류 데이터 | 측정·입력·변환이 잘못돼 신뢰할 수 없는 값 | 자료형, 단위, 컬럼 관계, 원자료 확인 | 근거가 있을 때 수정하거나 제외하고 처리 내용을 기록 |
| 이상 기온 | 같은 시기의 일반적인 범위에서 크게 벗어난 실제 기온 | 품질검사 통과 후 계절·월 기준과 비교 | 기상 현상을 설명할 분석 신호로 유지 |

세 개념은 서로 배타적인 분류가 아니다. 분포에서 멀리 떨어진 값은 먼저 이상치 후보가 된다. 이 단계에서는 오류인지 실제 현상인지 알 수 없다.

판단 순서는 다음과 같다.

1. 먼저 자료형, 단위와 컬럼 관계를 검사한다.
2. 값이 잘못됐다는 근거가 확인되면 오류 데이터로 처리한다.
3. 오류 근거가 없으면 같은 시기의 기온 분포와 비교한다.
4. 통계 기준에서 멀리 떨어졌다면 이상치 후보로 표시한다.
5. 실제 기상 관측으로 판단되면 이상 기온 후보로 분석한다.

예를 들어 2002-01-15의 일평균기온 12.2°C는 품질검사를 통과했다. 같은 1월 분포에서는 z 점수 `+3.236`으로 멀리 떨어져 있다. 따라서 오류 데이터가 아니라 통계적 이상 고온 후보다.

반대로 최저기온이 최고기온보다 높으면 컬럼 관계가 성립하지 않는다. 값이 아주 크거나 작지 않아도 오류 데이터로 판단할 근거가 된다.

이 프로젝트는 두 가지 기온 품질 조건을 검사한다.

- 평균·최저·최고기온이 `-50~50°C` 안에 있는가?
- `최저기온 ≤ 평균기온 ≤ 최고기온` 관계를 만족하는가?

두 조건은 의심 자료를 찾는 품질검사선이다. 값을 자동으로 삭제하는 규칙은 아니다. 실제 데이터에서는 위반이 0건이었다.

### 3.4 품질검사와 관측률

품질검사는 분석 전에 데이터가 정한 계약을 만족하는지 확인하는 절차다. 이 프로젝트는 기간, 지점번호, 필수 컬럼, 날짜 중복, 누락 날짜, 결측치, 값 범위와 변수 간 관계를 검사한다. 누락 날짜가 하나라도 있으면 분석을 중단한다.

관측률은 집계 구간에서 기대되는 날짜 중 유효한 관측값이 있는 비율이다.

```text
관측률 = 유효한 관측값 수 / 해당 기간에 기대되는 날짜 수
```

월평균에는 관측률 80% 기준을 적용한다. 연평균에는 95% 기준을 적용한다. 값이 몇 개 없는 기간의 평균은 그 기간을 대표하기 어렵기 때문이다.

실제 평균기온에는 결측이 없다. 따라서 372개 연-월과 31개 연도가 모두 기준을 통과했다.

품질검사 기준과 실제 처리 결과는 [분석 설계](../design/analysis-design.md)와 [분석 리포트](../../REPORT.md)의 3~4절에서 더 자세히 볼 수 있다.

## 4. 기초 통계

기초 통계는 많은 관측값을 몇 개의 수치로 요약한다. 요약은 정보를 압축하는 대신 일부 차이를 감춘다. 따라서 통계량이 어떤 특성을 보여 주고 무엇을 놓치는지 함께 이해해야 한다.

### 4.1 평균과 중앙값

평균은 모든 값을 더해 개수로 나눈 값이다. 전체적인 수준을 요약하고 기간 간 차이를 계산하기 쉬워 연평균·월평균 기온에 사용했다.

중앙값은 값을 크기순으로 놓았을 때 가운데 값이다. 극단적인 값의 영향을 평균보다 적게 받는다. 분포가 한쪽으로 치우치거나 매우 큰 값이 섞인 경우 평균과 함께 보면 중심을 더 잘 이해할 수 있다.

이 프로젝트의 핵심 기온 집계는 평균을 사용한다. 기온의 전체 수준을 비교하려는 질문에 맞춘 선택이다.

중앙값도 중요한 통계량이다. 분석 질문과 분포의 특성에 따라 적절한 중심값은 달라진다.

### 4.2 분산과 표준편차

평균만으로는 값들이 얼마나 퍼져 있는지 알 수 없다.

분산은 각 값과 평균의 거리를 이용한다. 그 거리를 제곱한 값의 평균이 분산이다. 표준편차는 분산의 제곱근이다.

표준편차는 원래 값과 같은 단위를 사용한다. 기온의 표준편차가 크면 같은 기간의 기온 변화 폭도 크다는 뜻이다.

이 프로젝트는 같은 달의 일별 기온 변동폭을 표준편차로 나타낸다. 일별 편차를 표준편차로 나누면 달마다 다른 변동성을 비교할 수 있다.

이때 선택한 1994~2024년 자료 전체를 분석 기준 집합으로 보고 모표준편차(`ddof=0`)를 사용했다. 이는 더 큰 모집단의 표준편차를 추정하는 표본표준편차와 목적이 다르다.

### 4.3 사분위수와 IQR

사분위수는 정렬된 데이터를 네 구간으로 나누는 기준값이다. IQR은 제1사분위수와 제3사분위수 사이의 범위다. 데이터의 가운데 50%를 나타낸다.

IQR은 극단값의 영향을 비교적 적게 받는다. 그래서 분포가 치우친 데이터에서 이상치 후보를 찾을 때 자주 사용한다.

이 프로젝트의 이상 기온 후보 기준에는 IQR을 사용하지 않았다. 달마다 다른 평균과 변동폭을 공통 척도로 비교하기 위해 z 점수를 선택했다.

IQR과 z 점수 중 하나가 항상 더 좋은 것은 아니다. 분포 형태와 분석 목적에 따라 선택해야 한다.

### 4.4 편차와 표준화

편차는 관측값에서 비교 기준을 뺀 값이다.

```text
기온 편차 = 관측 기온 - 비교 기준 기온
```

편차가 `+2°C`라면 기준보다 2°C 높다는 뜻이다. 그러나 같은 편차가 모든 달에서 같은 의미를 갖지는 않는다.

표준화는 편차를 해당 집단의 표준편차로 나눈다. 서로 다른 변동폭을 공통 척도로 바꾸기 위해서다.

```text
z 점수 = 편차 / 표준편차
```

z 점수 `+2.5`는 평균보다 2.5표준편차 높은 위치라는 뜻이다. 표준화했다고 해서 데이터가 정규분포가 되거나, 값의 원인이 설명되는 것은 아니다.

기초 통계 용어의 짧은 정의는 [데이터 분석 용어집](glossary.md)의 기초 데이터 분석 절에서 확인할 수 있다.

## 5. 시계열 분석

시계열 분석은 시간의 순서와 간격을 이용한다.

인접한 시점은 서로 관련될 수 있다. 같은 계절의 패턴도 반복될 수 있다. 이러한 특성이 일반적인 표 데이터와 다른 점이다.

### 5.1 트렌드, 계절성, 노이즈

- 트렌드는 장기간에 걸친 전반적인 상승 또는 하락 방향이다.
- 계절성은 일정한 시간 간격으로 반복되는 패턴이다.
- 노이즈는 트렌드와 계절성만으로 설명되지 않는 불규칙한 변동이다.

서울 기온은 여름에 높고 겨울에 낮다. 강한 계절성이 있기 때문이다.

계절성을 고려하지 않으면 1월과 8월을 공정하게 비교하기 어렵다. 하루 단위 변동도 크다. 그래서 장기 트렌드는 연평균이나 이동평균으로 살펴본다.

노이즈는 곧 오류라는 뜻이 아니다. 불규칙해 보이는 변동에도 실제 날씨 현상이 포함된다.

### 5.2 시간 단위 집계

집계는 일별 값을 월별·연도별 평균처럼 더 큰 시간 단위로 요약하는 과정이다. 집계 단위가 바뀌면 답할 수 있는 질문도 달라진다.

| 단위 | 보기 좋은 현상 | 감춰질 수 있는 현상 |
| --- | --- | --- |
| 일 | 짧은 이상 기온, 급격한 변화 | 장기 방향 |
| 월 | 계절 전환, 월별 차이 | 하루 극값 |
| 연 | 장기 추세, 연도 비교 | 월·계절 내부 차이 |

이 프로젝트는 장기 방향에는 연평균을, 계절 패턴에는 월평균을, 통계적 이상 기온에는 일평균을 사용한다. 하나의 집계 단위로 모든 질문에 답하지 않는다.

### 5.3 이동평균

이동평균은 현재 시점과 주변의 일정 기간 값을 계속 평균내는 방법이다. 짧은 변동을 완화해 비교적 느린 흐름을 보기 쉽게 한다.

이 프로젝트에서는 두 이동평균을 계산한다.

- 30일 후행 이동평균: 일별 기온의 짧은 변동 완화
- 5년 후행 이동평균: 연평균 기온의 장기 흐름 확인

후행 이동평균은 현재 시점과 과거 값만 사용한다. 5년 후행 이동평균이라면 현재 연도와 이전 4개 연도를 사용한다.

창이 커지면 그래프가 부드러워진다. 대신 변화가 늦게 나타나며 짧은 현상은 감춰진다. 따라서 이동평균은 원자료와 함께 해석해야 한다.

### 5.4 변화량과 기간 비교

변화량은 현재 값에서 이전 값을 뺀 차이다. 전년 대비 변화량은 해마다 기온이 얼마나 오르내렸는지 보여 준다. 반면 초기 10년과 최근 10년 평균 차이는 두 기간의 전반적인 수준을 비교한다.

이 프로젝트에서 최근 10년 평균은 초기 10년보다 0.66°C 높았다. 그러나 두 기간 비교는 시작·종료 연도 선택에 영향을 받는다. 하나의 차이만 보고 매년 일정하게 상승했다고 해석하면 안 된다.

### 5.5 평년값과 분석용 기준선

[평년값](glossary.md#평년값-climatological-normal)은 관측값을 비교하기 위한 장기간 평균 기준이다. 기상학에서는 정해진 표준 기간의 공식 기후평년을 사용한다.

이 프로젝트는 1994~2024년 월별 평균을 `분석용 기준선`으로 사용한다. 공식 기후평년과는 다른 값이다.

기준 기간이 달라지면 편차와 이상 기온 후보도 바뀔 수 있다. 따라서 편차를 제시할 때는 무엇을 기준으로 뺐는지 반드시 밝혀야 한다.

### 5.6 선형 추세와 결정계수

선형 추세는 시간과 값의 관계를 직선으로 요약한다. 이 프로젝트는 연도를 설명변수, 연평균 기온을 반응변수로 두었다.

- 기울기 `+0.302°C/10년`: 선택 기간에서 직선으로 요약한 평균 상승 속도
- R² `0.187`: 연도라는 한 변수가 연평균 기온의 변동을 직선 관계로 설명하는 정도

R² `0.187`은 이 단순 모델이 연평균 기온 변동의 약 18.7%를 설명한다는 뜻이다. 대상은 선택한 31개 연평균이다.

기울기는 상승 방향을 나타낸다. 하지만 이 모델은 연도별 변동의 대부분을 설명하지 못한다.

선형 추세는 다음을 말해 주지 않는다.

- 상승의 원인이 무엇인지
- 미래에도 같은 속도로 상승할지
- 분석기간 내부의 비선형 변화가 어떤지
- 특정 연도의 기온이 왜 높거나 낮았는지

계산 기준과 시각화 설계는 [분석 설계](../design/analysis-design.md)의 6절과 [분석 리포트](../../REPORT.md)의 5~6절에 정리돼 있다.

## 6. 통계적 이상 기온

### 6.1 왜 같은 달끼리 비교하는가

서울의 30°C는 여름에는 흔할 수 있지만 겨울에는 그렇지 않다. 모든 날짜를 하나의 평균과 비교하면 계절성 때문에 여름은 대부분 고온, 겨울은 대부분 저온으로 분류될 수 있다.

이 프로젝트는 각 날짜를 같은 달의 1994~2024년 기온 분포와 비교한다.

```text
월내 기온 편차 = 일평균기온 - 같은 달의 장기 평균
z 점수 = 월내 기온 편차 / 같은 달의 모표준편차
```

이렇게 하면 절대기온이 아니라 “해당 달에 비해 얼마나 이례적인가”를 비교할 수 있다.

### 6.2 z 점수와 임계값

이 프로젝트의 탐색 기준은 다음과 같다.

- `z ≥ +2.5`: 통계적 이상 고온 후보
- `z ≤ -2.5`: 통계적 이상 저온 후보

고온 후보는 43일이었다. 저온 후보는 98일이었다.

가장 큰 고온 후보는 1월에 나타났다. 가장 큰 저온 후보는 6월에 나타났다. 통계적 이상 기온은 한여름의 최고기온이나 한겨울의 최저기온과 다른 개념이다.

`±2.5`는 드문 관측을 탐색하기 위한 임계값이다. 값을 낮추면 후보가 늘어난다. 높이면 후보가 줄어든다.

실제 분포가 정규분포인지는 검증하지 않았다. 따라서 z 점수만으로 발생 확률을 단정하지 않는다.

### 6.3 통계적 후보와 공식 기상 기준

통계적 이상 기온 후보는 다음과 구분해야 한다.

- 관측 오류: 잘못 측정되거나 기록된 값
- 공식 폭염일: 기상청이 정한 일최고기온 기준을 충족한 날
- 공식 열대야: 정해진 야간 시간의 최저기온 기준을 충족한 날
- 이 프로젝트의 후보: 같은 달의 분포에서 z 점수 `±2.5`를 벗어난 일평균기온

따라서 후보를 “기상청이 판정한 이상기후”라고 표현하면 안 된다. 데이터에서 삭제해서도 안 된다.

후보는 원인을 조사할 대상이다. 월 단위 비교에서 찾은 탐색 결과이기 때문이다.

월 단위 기준은 월 안의 계절 진행을 완전히 제거하지 못한다. 월초와 월말의 일반적인 기온이 다를 수 있기 때문이다.

더 정교한 분석에서는 날짜 전후의 이동 기준기간이나 일별 평년값을 사용할 수 있다. 이 한계는 [분석 리포트](../../REPORT.md)의 인사이트 3에 기록돼 있다.

## 7. 결과 해석

분석에서 가장 중요한 능력은 계산된 값과 그 값에 대한 설명을 구분하는 것이다.

### 7.1 관찰, 해석, 가설

관찰은 데이터와 그래프에서 직접 확인할 수 있는 사실과 패턴이다. 해석은 관찰이 무엇을 의미하는지 설명하는 판단이다. 가설은 관찰의 가능한 원인을 설명하며 추가 자료로 검증해야 하는 주장이다.

| 구분 | 이 프로젝트의 예 |
| --- | --- |
| 관찰 | 연평균 선형 추세는 `+0.302°C/10년`이다. |
| 관찰 | 최근 10년 평균은 초기 10년보다 `0.66°C` 높다. |
| 해석 | R²가 `0.187`이므로 상승 추세만으로 연도별 변동 대부분을 설명하기 어렵다. |
| 가설 | 도시화나 광역 기후 변화가 상승에 영향을 줬을 수 있다. |

앞의 두 관찰은 코드로 다시 계산할 수 있다.

마지막 가설에는 추가 자료가 필요하다. 도시화 지표와 다른 관측소 자료가 예다. 광역·전지구 기온도 함께 살펴야 한다. 가능성만으로 가설을 사실처럼 쓰면 안 된다.

이 프로젝트의 인사이트는 다음 네 가지 필수 부분으로 작성하고, 원인을 제안할 때만 가설을 별도로 추가했다.

1. 관찰(Fact): 그래프와 수치에서 확인한 내용
2. 해석(Interpretation): 관찰이 분석 질문에 대해 의미하는 바
3. 가설(Hypothesis): 관찰의 가능한 원인에 대한 검증 전 설명이며 필요한 경우에만 작성
4. 한계(Limit): 현재 자료만으로 확인할 수 없는 부분
5. 행동(Action): 추가 분석이나 의사결정 방향

### 7.2 상관관계와 인과관계

상관관계는 두 값이 함께 변하는 경향이다. 인과관계는 한 요인의 변화가 다른 결과를 일으켰다는 주장이다.

연평균 기온은 시간에 따라 상승했다. 그렇다고 시간이 기온을 올렸다는 뜻은 아니다.

단일 기온 시계열만으로는 각 원인의 기여도를 분리할 수 없다. 온실가스, 도시화와 특정 기상현상은 별도의 자료가 필요하다. 인과관계를 주장하려면 대안 설명을 검토할 연구 설계도 필요하다.

### 7.3 분석 범위와 일반화

이 프로젝트의 결과는 서울 ASOS 지점 `108`의 1994~2024년 자료에 대한 것이다. 다음과 같이 범위를 확장해 말할 수 없다.

- 서울 모든 동네가 같은 크기로 변했다.
- 대한민국 전체가 같은 추세를 보였다.
- 미래에도 같은 기울기로 상승한다.
- 상승 원인은 특정 요인 하나다.

분석의 한계는 결과를 약하게 만드는 변명이 아니다. 결론이 적용되는 범위를 정확히 정하는 분석 결과의 일부다.

### 7.4 그래프를 읽는 순서

시각화는 다음 순서로 읽으면 과도한 해석을 줄일 수 있다.

1. 제목과 분석 기간을 확인한다.
2. x축·y축, 단위와 집계 수준을 확인한다.
3. 실제 관측값과 이동평균·추세선·기준선을 구분한다.
4. 눈에 띄는 패턴을 수치로 확인한다.
5. 관찰과 가능한 원인을 별도 문장으로 적는다.
6. 그래프에 포함되지 않은 변수와 한계를 확인한다.

실제 적용 예시는 [분석 리포트](../../REPORT.md)의 6~8절에서 확인할 수 있다.

## 8. 재현성과 추적 가능성

### 8.1 데이터 출처와 데이터 계보

데이터 출처는 관측기관과 제공 방식을 나타낸다.

다운로드가 편리하다는 이유만으로 출처가 불분명한 데이터를 사용하면 안 된다. 값의 정의와 단위를 검증하기 어렵다. 품질관리 방식과 이용조건도 알기 어렵다.

데이터 계보는 원자료가 어떤 과정을 거쳐 최종 그래프와 통계가 됐는지 추적하는 흐름이다.

```text
기상청 연도별 원자료
→ 컬럼·자료형 표준화
→ 31개 연도 통합
→ 데이터 품질검사
→ 집계·추세·z 점수 계산
→ 요약 JSON과 PNG
→ README와 REPORT
```

이 흐름을 기록하면 결과가 잘못됐을 때 어느 단계에서 문제가 생겼는지 찾을 수 있다.

### 8.2 해시

해시는 파일 내용으로 계산한 고정 길이 값이다. 내용이 바뀌면 일반적으로 해시도 달라진다.

이 프로젝트는 SHA-256을 사용한다. 내려받은 원자료와 가공 CSV가 검증 때와 같은지 확인하기 위해서다.

해시가 같다는 사실은 파일 내용이 같다는 강한 근거지만, 데이터가 현실을 정확히 관측했다는 뜻은 아니다. 파일 무결성과 관측 정확성은 서로 다른 품질 문제다.

### 8.3 재현성

재현성은 같은 원자료, 코드, 환경과 절차를 사용했을 때 같은 분석 결과를 다시 만들 수 있는 성질이다. 재현 가능한 분석에는 다음이 필요하다.

- 출처와 수집 기간
- 변경되지 않은 원자료
- 정제·계산 코드
- 라이브러리와 버전
- 실행 순서
- 검증 가능한 중간·최종 산출물

manifest에는 원본 파일명·크기·SHA-256을 기록한다. `requirements.txt`에는 라이브러리 버전을 고정한다.

패키지와 콘솔 명령은 같은 workflow를 호출한다. 자동 테스트는 데이터 계약과 계산 결과를 확인한다.

재현성만으로 결과가 과학적으로 옳다고 판단할 수는 없다. 잘못된 가정도 같은 방식으로 반복할 수 있기 때문이다.

따라서 재현 가능성만 확인해서는 안 된다. 데이터 품질, 분석 방법과 해석도 각각 검토해야 한다.

구현 흐름은 [과제 아키텍처](../design/architecture.md), 검증 기준과 실행 증적은 [검증 계획](../guides/verification-plan.md)에서 확인할 수 있다.

## 개념을 읽는 권장 순서

처음에는 모든 통계 용어를 외우려 하지 말고 다음 질문이 이어지는 흐름을 이해하는 것이 좋다.

1. 한 행과 한 열은 무엇을 의미하는가?
2. 값이 비었거나 중복됐을 때 결과가 어떻게 달라지는가?
3. 평균은 무엇을 보여 주고 무엇을 감추는가?
4. 시간 단위를 바꾸면 어떤 패턴이 보이는가?
5. 이동평균과 선형 추세는 서로 어떤 질문에 답하는가?
6. 드문 값과 잘못된 값은 어떻게 구분하는가?
7. 그래프에서 확인한 사실과 가능한 원인을 어떻게 분리하는가?
8. 다른 사람이 같은 결과를 다시 만들 수 있는가?

이 질문에 자신의 말로 답할 수 있다면 핵심 개념을 이해한 것이다.

용어의 짧은 정의는 [데이터 분석 용어집](glossary.md)에서 찾을 수 있다. 실제 수치와 결론은 [분석 리포트](../../REPORT.md)에서 확인한다. 각 학습 목표가 프로젝트에 적용된 과정은 [과제 목표](objectives.md)에서 확인한다.
