# M1-1 에이전트 작업 지침

## 적용 범위

이 지침은 `M1-1/` 디렉터리와 모든 하위 파일에 적용한다.

## 작업 원칙

- 사용자 승인 없이 Git 커밋을 생성하지 않는다.
- Git에서 제외된 파일은 산출물 문서, 파일 구조, 실행 결과에 언급하거나 추가하지 않는다.
- 사용자에게 보이는 프로젝트 소개는 루트 `README.md`에 작성한다.
- 상세 요구사항과 설계는 `docs/` 아래에서 주제별로 관리한다.
- 문서와 구현이 충돌하면 먼저 문서를 갱신하고 승인된 요구사항을 기준으로 구현한다.
- 프로젝트 문서와 사용자 안내는 한국어로 작성한다.

## 요구사항 우선순위

1. `docs/requirements.md`
2. `docs/data-source.md`와 `docs/analysis-design.md`
3. `docs/architecture.md`와 `docs/verification-plan.md`

요구사항을 임의로 축소하거나 확장하지 않는다. 분석 기간, 관측 지점, 데이터 출처, 결측치 처리, 이상 기온 기준을 변경하려면 변경 이유와 영향을 먼저 문서화한다.

## 데이터 규칙

- 기상청 ASOS 서울 지점 `108`의 1994~2024년 일자료를 기본 데이터로 사용한다.
- 원본 ZIP과 CSV는 수정하지 않는다.
- 원본과 가공 데이터를 별도 디렉터리에 보관한다.
- 결측치를 임의로 `0`으로 바꾸거나 보간하지 않는다.
- 이상 기온 후보를 단순 이상치로 판단해 삭제하지 않는다.
- 다른 출처의 데이터를 승인 없이 혼합하거나 대체하지 않는다.
- 데이터 출처, 접근일, 파일명과 SHA-256 해시를 기록한다.

## 구현 규칙

- Python 3.10 이상을 기준으로 한다.
- 모든 Python 구현은 `src/seoul_weather/` 패키지 아래에 둔다.
- 수집(`collection`), 정규화(`processing`), 분석(`analytics`), 시각화(`visualization`), 실행 흐름(`workflows`)을 책임별로 분리한다.
- `python -m seoul_weather` 패키지 실행과 `seoul-weather` 콘솔 실행은 동일한 CLI와 workflow를 공유한다.
- `download`, `analyze`, `run` 명령을 제공하며 `run`은 준비 단계와 분석을 순서대로 수행한다.
- 계산 로직과 파일 입출력을 분리해 단위 테스트가 가능하도록 작성한다.
- 네트워크 단위 테스트는 실제 서버 대신 fixture를 사용한다.
- 오류 HTML을 ZIP으로 처리하지 않도록 파일 형식을 검증한다.
- 필수 연도, 컬럼 또는 날짜가 누락되면 조용히 건너뛰지 않고 명시적으로 실패한다.
- 생성 파일명과 디렉터리는 `docs/architecture.md`를 따른다.

## 검증 규칙

- 완료를 보고하기 전에 `docs/verification-plan.md`의 검증 항목을 수행한다.
- 최소한 데이터 수집, 분석 스크립트 실행, `pytest`를 새 환경에서 확인한다.
- 테스트 실패나 미검증 항목이 있으면 완료로 표현하지 않는다.
- 관찰과 해석이 분리됐는지 사람이 최종 검토한다.
- 그래프 파일과 REPORT의 이미지 링크가 실제로 열리는지 확인한다.

## README 결과 반영

- 구현 전 README의 결과물 예시는 실제 결과가 아님을 명확히 표시한다.
- 실제 분석 전에는 임의의 수치나 가상의 그래프를 실제 결과처럼 작성하지 않는다.
- 데이터 수집과 분석 검증이 끝나면 README에 실제 데이터 수, 기간, 결측 현황과 핵심 통계를 반영한다.
- 생성된 그래프 3개를 README에서 직접 볼 수 있도록 이미지 3개와 링크를 추가한다.
- 핵심 인사이트와 `REPORT.md` 링크를 추가한다.
- README의 모든 수치는 `seoul-weather analyze` 출력과 테스트로 검증한다.
- 실제 결과 반영 후에는 결과물 예시와 실제 결과가 혼동되지 않도록 예시 안내를 실제 결과 설명으로 갱신한다.
