# 중복 리뷰 처리 정책

- 작성일: 2026-08-05
- 적용 범위: `import`, `clean` 및 파생 분석 데이터

## 1. 목적

같은 리뷰를 반복 수집해 통계가 왜곡되는 것을 막으면서, 수정된 부가 정보는 명시적인 `upsert` 정책으로 반영한다. 원문 보존, 재현 가능한 중복 판정, 파생 데이터 일관성을 동시에 보장한다.

## 2. 중복 식별자

중복 식별자는 다음 세 구성요소를 정규화한 뒤 순서가 고정된 JSON 배열로 직렬화하고 SHA-256 해시를 계산한 값이다.

1. 리뷰 본문
2. 제품명
3. 작성일

구성요소 사이에 단순 구분자를 붙이지 않고 JSON 배열을 사용하는 이유는 값 자체에 구분자가 포함되어도 충돌하지 않게 하기 위해서다.

### 2.1 정규화 규칙

리뷰 본문과 제품명에는 다음 규칙을 순서대로 적용한다.

1. 값이 없으면 빈 문자열로 치환한다.
2. 문자열로 변환한다.
3. Unicode NFKC 정규화를 적용한다.
4. 앞뒤 공백을 제거한다.
5. 탭·줄바꿈을 포함한 연속 공백을 공백 하나로 축약한다.
6. 대소문자 차이로만 중복을 피하지 못하도록 `casefold`를 적용한다.

작성일은 파싱 가능하면 `YYYY-MM-DD`로 변환한다. 파싱할 수 없으면 원문 문자열에 텍스트 정규화 규칙을 적용한다. 값이 없으면 빈 문자열을 사용한다.

```text
fingerprint = SHA256(JSON([normalized_text, normalized_product, normalized_date]))
```

별점은 식별자에 포함하지 않는다. 같은 리뷰의 별점이 수정된 경우 `upsert`로 반영할 수 있어야 하기 때문이다.

## 3. 정책 선택

기본 정책은 `config.json`의 `duplicate_policy`에서 읽고 초기값은 `skip`이다. `import`의 `--duplicate-policy skip|upsert` 옵션이 있으면 해당 실행에서만 설정값을 덮어쓴다.

### 3.1 `skip`

- 기존 지문과 일치하면 새 raw 행을 만들지 않는다.
- 기존 raw, clean, 감정 분석, 인사이트 상태를 변경하지 않는다.
- 처리 결과의 스킵 건수와 INFO 로그에 포함한다.

### 3.2 `upsert`

- 기존 지문과 일치하면 같은 `raw_reviews.id`를 유지한다.
- 리뷰 원문 및 선택 필드, 입력 출처, 수정 시각을 새 입력값으로 갱신한다.
- raw의 `clean_status`를 `pending`으로 되돌리고 `rejection_reason`을 비운다.
- 연결된 `clean_reviews`를 제거하고 외래 키 cascade로 현재 감정 분석 결과를 제거한다.
- 모든 집계형 `insight_extractions`를 `is_stale = true`로 표시한다.
- 이후 `clean`, `analyze`, `extract`를 순서대로 다시 실행해야 최신 리포트를 얻을 수 있다.

파생 데이터를 무효화하는 이유는 별점·원문 부가 정보 변경이 정제 결과, 별점·감정 일치율, 필터 범위, 요약에 영향을 줄 수 있기 때문이다.

## 4. raw와 clean의 관계

중복 판정은 raw 저장 직전에 수행하지만 정규화 값은 식별 계산에만 사용한다. `review_text_raw`, `rating_raw`, `review_date_raw`, `product_name_raw`에는 입력값을 그대로 보존한다.

정제된 값은 `clean` 명령에서 별도의 `clean_reviews` 행으로 만든다. raw 한 건에는 최대 하나의 현재 clean 행만 연결된다.

## 5. 트랜잭션과 동시성

한 행의 중복 확인과 insert/upsert, 파생 데이터 무효화는 하나의 SQLite 쓰기 트랜잭션에서 수행한다. `fingerprint`에 UNIQUE 제약을 두어 동시에 같은 리뷰가 들어와도 중복 행이 만들어지지 않게 한다.

파일 import는 행별 실패를 격리하되 각 행의 DB 변경은 원자적으로 처리한다. 파일을 읽지 못하거나 필수 `review_text` 열이 없으면 어떤 행도 저장하지 않는다.

## 6. 경계 사례

| 사례 | 판정 |
| --- | --- |
| 본문 공백·줄바꿈만 다름 | 중복 |
| 본문 대소문자만 다름 | 중복 |
| Unicode 표현만 다름 | 중복 |
| 같은 본문·제품·날짜, 별점만 다름 | 중복; upsert로 별점 갱신 가능 |
| 같은 본문, 제품이 다름 | 별도 리뷰 |
| 같은 본문·제품, 날짜가 다름 | 별도 리뷰 |
| 본문만 있고 제품·날짜가 모두 없음 | 정규화 본문이 같으면 중복 |
| 작성일이 서로 다른 형식이지만 같은 날짜 | 중복 |
| 파싱 불가능한 작성일 문자열이 다름 | 별도 리뷰 |

제품명과 작성일이 없는 동일 문구 리뷰가 실제로 서로 다른 고객에게서 작성되었을 가능성은 있다. 입력에 외부 리뷰 ID가 필수라는 요구사항이 없으므로, 이번 범위에서는 통계 중복 방지를 우선해 동일 리뷰로 처리한다.

## 7. 필수 테스트

- 정규화 규칙별 동일 지문 생성
- 제품명 또는 날짜가 다를 때 다른 지문 생성
- 별점 차이가 지문에 영향을 주지 않음
- `skip`이 기존 및 파생 데이터를 변경하지 않음
- `upsert`가 raw ID를 보존하고 clean·감정 결과를 무효화함
- `upsert`가 집계 인사이트를 stale 처리함
- UNIQUE 충돌 시 중복 raw 행이 생성되지 않음
