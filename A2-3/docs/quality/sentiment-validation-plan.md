# 감정 분석 정확도 검증과 프롬프트 실험 계획

- 상태: 실행 전 검증 계획
- 대상 출력: `positive`, `negative`, `neutral`, confidence `0.0..1.0`
- 추적 키: 모델 이름과 `prompt_version`
- 프롬프트 계약: [`../analysis/prompt-design.md`](../analysis/prompt-design.md)

현재 저장소에는 네트워크 없는 기능 테스트와 Gemini 구조화 응답 검증이 있지만, 사람이 만든 정답셋에 대한 정확도 실험 결과는 없다. 이 문서는 실험 절차와 합격 기준을 정의하며, 실제 성능 수치를 주장하지 않는다.

## 1. 검증 질문

1. 세 감정 클래스가 사람이 합의한 라벨과 얼마나 일치하는가?
2. 부정 리뷰를 놓치는 비율과 긍정·중립을 부정으로 잘못 분류하는 비율은 얼마인가?
3. confidence가 높은 결과가 실제로 더 정확한가?
4. 특정 상품, 별점, 기간, 본문 길이에서 오류가 집중되는가?
5. 프롬프트 변경이 동일 정답셋에서 재현 가능한 개선을 만드는가?

## 2. 층화 샘플링

### 2.1 표본 크기

- 탐색·라벨 지침 점검 회차의 기본 목표는 고유 리뷰 100건이다. 이 표본은 오류 유형을 찾는 데 사용하며 프롬프트 운영 전환의 단독 근거로 사용하지 않는다.
- 운영 전환 비교는 고유 리뷰 300건 이상과 정답 클래스별 75건 이상을 목표로 한다. 전체 분석 완료 리뷰가 300건 미만이면 전수 검수하고 표본 한계를 결과에 기록한다.
- 탐색 회차에서도 가능하면 예측 감정별 최소 20건을 확보한다.
- 상품별로 최소 10건을 확보하되 상품 수가 많으면 거래량 상위 상품과 무작위 기타 상품 층을 나눈다.
- 최근 데이터 70%, 이전 데이터 30%를 기본으로 해 현재 오류와 시간 변화 모두를 확인한다.

### 2.2 층화 기준

다음 층을 조합해 무작위 추출한다.

- 예측 감정: positive, neutral, negative
- 별점: 1~2, 3, 4~5, 누락
- 상품: 주요 `product_name`과 기타
- 기간: 최근 구간과 과거 구간
- 본문 길이: 짧음, 중간, 긺. 해당 데이터의 33·67 분위수로 경계를 계산
- confidence: 0.6 미만, 0.6 이상 0.8 미만, 0.8 이상
- 별점·감정 기대 불일치 여부

대표 성능 표본에서는 각 리뷰가 하나의 상호 배타적 최종 층에만 속하게 한다. 기본 층은 `예측 감정 × 별점 구간 × 주요 상품/기타`의 조합이며, 셀의 모집단이나 목표 표본이 5건 미만이면 인접 별점 구간부터 합친다. 기간·본문 길이·confidence·별점 불일치는 표본 배정 뒤 층별 진단 변수로 사용한다.

각 최종 층 `h`의 모집단 크기 `N_h`, 무작위 추출 크기 `n_h`, 난수 seed를 기록하고 리뷰별 설계 가중치를 `w_h = N_h / n_h`로 둔다. 대표 전체 Accuracy와 confusion matrix는 이 가중치를 적용하고, 클래스별 precision·recall·Macro F1도 가중 confusion matrix에서 계산한다. 비가중 결과를 함께 남겨 과표집의 영향을 확인한다.

저신뢰와 별점·감정 불일치 리뷰는 오류 분석용 진단 표본으로 추가 추출할 수 있지만 대표 성능 메트릭에는 합치지 않는다. 진단 표본은 별도 표에서 오류 유형과 건수만 보고한다. 중복 지문은 하나의 리뷰로 취급해 반복 문구가 결과를 부풀리지 않게 한다.

## 3. 사람 검수 절차

1. 검수용 파일에는 `review_id`, 익명화된 본문, 필요한 최소 맥락만 제공한다. 모델 예측과 confidence는 숨긴다.
2. 두 명의 검수자가 독립적으로 positive, neutral, negative 중 하나를 선택하고 판단 근거와 모호성 사유를 기록한다.
3. 비꼼, 복합 감정, 단순 사실 서술, 상품이 아닌 배송·서비스 평가에 대한 공통 라벨 지침을 먼저 20건으로 예행 검수한다.
4. 두 라벨이 같으면 잠정 정답으로 채택한다.
5. 불일치는 제3 검수자 또는 합의 회의로 조정하며, 원래 두 라벨과 최종 근거를 모두 보존한다.
6. 합의가 불가능한 리뷰는 `ambiguous`로 별도 표시하고 주 메트릭 분모에서는 제외하되 건수와 비율을 보고한다.
7. 확정 정답셋은 버전, 추출 조건, 생성일, 검수자, 라벨 지침 버전과 함께 동결한다.

개인정보와 전체 리뷰 본문은 공개 실험 로그에 넣지 않는다. 외부 공유가 필요하면 비식별화하고 접근 권한을 제한한다.

## 4. 정량 메트릭

| 메트릭 | 목적 | 해석 시 주의점 |
| --- | --- | --- |
| Accuracy | 전체 정답 비율 | 클래스 불균형이 크면 다수 클래스 성능에 가려짐 |
| Macro F1 | 세 클래스 F1의 동일 가중 평균 | 클래스별 균형 성능을 주 판단 지표로 사용 |
| 클래스별 Precision | 해당 감정 예측 중 실제 정답 비율 | 부정 precision이 낮으면 불필요한 경보 증가 |
| 클래스별 Recall | 실제 해당 감정을 찾아낸 비율 | 부정 recall이 낮으면 중요한 불만 누락 |
| Confusion matrix | 어떤 클래스를 서로 혼동하는지 확인 | 건수와 행 기준 비율을 함께 표시 |
| Cohen's kappa | 두 사람 검수자의 우연 일치 보정 합의도 | 낮으면 모델보다 라벨 지침을 먼저 개선 |
| Confidence 구간별 경험 정확도 | 점수 구간이 높을수록 실제 정답률도 높아지는지 탐색 | 확률 보정 지표가 아니라 순서성과 오류 집중을 보는 참고 지표 |
| ECE·Brier score | confidence가 정답 확률로 계약된 이후 보정 평가 | 현재 응답 계약에서는 계산하지 않음 |

현재 API 응답은 confidence가 `0.0..1.0` 범위라는 것만 보장하며 정답 확률이나 보정된 확률이라는 의미를 정의하지 않는다. 따라서 ECE와 Brier score를 계산하거나 `0.8`을 확률 임계치로 해석하지 않는다. 현 계약에서는 `<0.6`, `0.6..0.8`, `≥0.8` 구간의 표본 수와 경험 정확도를 기술통계로 보고, 구간이 높아질수록 정확도가 일관되게 증가하는지만 탐색한다. 확률 보정 평가는 모델 제공 문서와 응답 계약이 confidence의 확률적 의미를 보장한 뒤 별도 계획으로 승인한다.

## 5. 초기 합격 기준

정답셋이 확정된 뒤 다음을 모두 만족해야 운영 기준을 통과한 것으로 판정한다.

- Macro F1 0.80 이상
- negative recall 0.80 이상
- 각 클래스 recall 0.70 이상
- 검수자 간 Cohen's kappa 0.80 이상. 미만이면 모델 비교 전에 라벨 지침과 정답셋을 재검토
- 상품·별점·본문 길이 주요 층 중 전체 대비 Macro F1이 0.10 이상 낮은 취약층이 있으면 원인과 완화 계획을 기록

Confidence 구간별 경험 정확도는 합격 조건이 아니라 진단 결과로 기록한다. 점수와 정확도의 순서가 반복 회차에서 역전되면 운영자가 confidence를 정렬·필터 판단 근거로 사용하지 않도록 표시한다.

이 값은 초기 운영 기준이다. 표본 수와 오류 비용을 검토해 변경할 수 있지만, 결과를 본 뒤 특정 실험만 통과시키기 위해 기준을 소급 변경하지 않는다. 기준 변경은 다음 실험부터 적용하고 변경 이유와 날짜를 기록한다.

## 6. 프롬프트 개선 실험

### 6.1 비교 원칙

1. 기존 prompt version을 대조군, 변경 버전을 실험군으로 둔다.
2. 모델 이름, temperature 등 생성 설정, 정답셋, 배치 구성은 동일하게 고정한다.
3. 정답 라벨은 모델 출력과 프롬프트 버전을 가린 상태로 확정한다.
4. 각 버전을 동일 리뷰에 실행하고 review ID별 예측 차이를 보존한다.
5. 전체 메트릭뿐 아니라 negative recall, 클래스별 confusion, 저신뢰·복합 감정 오류를 비교한다.
6. 비용, 처리 시간, 구조화 응답 실패율도 함께 기록한다.

### 6.2 후보 승인 기준

후보 프롬프트는 5절의 절대 합격 기준을 만족하면서, 동일 리뷰에 대한 짝지은 bootstrap 10,000회로 계산한 차이의 95% 신뢰구간이 다음 비회귀 조건을 모두 충족해야 한다. 표본이 300건 또는 정답 클래스별 75건보다 적으면 결과는 탐색 회차로만 기록하고 운영 프롬프트를 전환하지 않는다.

- Macro F1 차이의 95% 신뢰구간 하한이 `-0.01` 이상
- negative recall 차이의 95% 신뢰구간 하한이 `-0.03` 이상
- 다른 각 클래스 recall 차이의 95% 신뢰구간 하한이 `-0.05` 이상
- 구조화 응답 실패율이 대조군보다 높아지지 않음
- 목표 오류 유형을 개선하려는 변경이라면 해당 오류의 짝지은 비교에서 McNemar 검정 `p < 0.05`이고 순개선 방향이거나, Macro F1 차이의 95% 신뢰구간 하한이 `0`보다 큼

Bootstrap은 층화 표본 설계를 유지하도록 최종 층 안에서 review ID를 재표집하고 설계 가중치를 적용한다. 구조화 응답 실패율은 동일 요청 단위로 비교하며, 차이가 한 건 이상이면 원인과 재시도 결과를 검토한다. 신뢰구간이 기준을 가로지르거나 McNemar 검정 조건을 만족하지 못하면 개선으로 확정하지 않고 표본을 추가하거나 다음 데이터 회차에서 재검증한다.

## 7. 오류 분석과 개선 순환

```text
층화 샘플 추출
  → 독립 이중 라벨링과 합의
  → 대조군 메트릭 계산
  → confusion matrix에서 목표 오류 선정
  → 한 번에 하나의 프롬프트 가설 변경
  → 동일 정답셋 A/B 실행
  → 합격·비회귀 기준 확인
  → 채택 또는 기각과 근거 기록
  → 새 운영 데이터로 재검증
```

프롬프트 변경 예시는 복합 감정의 우세 감정 규칙 명시, 비꼼 예시 추가, 배송과 상품 평가의 귀속 규칙 명시다. 여러 요소를 동시에 바꾸면 개선 원인을 식별하기 어려우므로 한 실험에서는 하나의 가설만 검증한다.

## 8. 실험 기록 양식

각 실행에서 아래 항목을 한 행 또는 하나의 실험 문서로 남긴다.

| 항목 | 기록 내용 |
| --- | --- |
| 실험 식별자 | 날짜와 목적을 포함한 고유 ID |
| 대조군 / 후보 | 모델 이름, prompt version, 프롬프트 변경 요약 |
| 가설 | 줄이려는 오류 유형과 기대 변화 |
| 정답셋 | 데이터 버전, 표본 수, 층화 조건, ambiguous 제외 건수 |
| 검수 품질 | 검수자 수, 합의 절차, Cohen's kappa |
| 표본 설계 | 최종 층별 `N_h`, `n_h`, `N_h/n_h`, 난수 seed, 진단 표본 수 |
| 결과 | 가중·비가중 Accuracy, Macro F1, 클래스별 precision/recall, confidence 구간별 경험 정확도, 실패율 |
| 층별 결과 | 상품, 별점, 기간, 길이, confidence별 성능 |
| 비용·성능 | 요청 수, 입력·출력 토큰, 평균·p95 처리 시간 |
| 오류 사례 | 비식별 review ID, 정답, 두 예측, 오류 범주 |
| 결정 | 채택·기각·재실험 중 하나와 기준 대비 근거 |
| 후속 조치 | 라벨 지침, 프롬프트, 데이터 수집 중 변경할 항목 |

실험을 수행하지 않은 상태에서는 결과 칸을 임의 수치로 채우지 않는다. 실행 기록과 정답셋 버전이 없는 성능 주장은 프로젝트 문서에 게시하지 않는다.
