# Raw 데이터와 Clean 데이터

- 처리 흐름: [`../data-flow.md`](../data-flow.md)

## Raw 데이터란

Raw 데이터는 외부에서 들어온 값을 가능한 한 원래 모습 그대로 보존한 데이터다. 아직 업무 규칙에 따라 유효하다고 확정되지 않았다.

예를 들어 CSV에 다음 행이 들어올 수 있다.

```text
review_text="  배송이\n\n너무 늦었어요  "
rating="2.0"
review_date="2026/8/5"
product_name=" 텀블러 "
```

raw 저장의 목적은 다음과 같다.

- 입력 원문 추적
- 잘못된 데이터의 원인 확인
- 정제 규칙 변경 후 재처리
- 원본과 분석 결과 사이의 감사 가능성 확보

이 프로젝트에서는 `import`와 `add`가 `raw_reviews`만 생성한다.

## Clean 데이터란

Clean 데이터는 raw 데이터에 검증과 정규화 규칙을 적용하여 분석과 조회에 안전하게 사용할 수 있게 만든 데이터다.

위 raw 예시는 다음 clean 데이터가 된다.

```text
review_text="배송이 너무 늦었어요"
rating=2
review_date="2026-08-05"
product_name="텀블러"
```

이 프로젝트의 주요 정제 규칙은 다음과 같다.

- 필수 리뷰 본문 존재 확인
- Unicode NFKC 정규화
- 앞뒤 공백 제거와 연속 공백 축약
- 별점을 정수 1~5로 검증
- 날짜를 `YYYY-MM-DD`로 통일
- 최소 본문 길이 검증

유효하지 않은 raw는 삭제하지 않고 `rejected` 상태와 사유를 남긴다. 기존 clean이 있는 raw를 다시 정제했는데 새 결과가 유효하지 않다면 기존 clean과 감정 결과를 제거하고 모든 집계 인사이트를 stale 처리한다.

## Raw와 Clean의 차이

| 비교 항목 | Raw | Clean |
| --- | --- | --- |
| 의미 | 수집된 원본 | 분석 가능한 검증·정규화 데이터 |
| 생성 명령 | `import`, `add` | `clean` |
| 값 보존 | 입력 표현을 그대로 유지 | 표준 형식으로 변환 |
| 유효성 보장 | 없음 | 본문·별점·날짜·길이 규칙 통과 |
| 분석 대상 | 아님 | Gemini 감정 분석 대상 |
| 오류 데이터 | 포함 가능 | 포함하지 않음 |
| 재생성 | 원본이므로 유지 | raw와 정제 규칙으로 재생성 가능 |

raw와 clean을 분리하면 정제 실수로 원본을 잃지 않고, 정제 규칙이 바뀌어도 외부 파일을 다시 구하지 않고 재처리할 수 있다.
