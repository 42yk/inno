# 백엔드 API 연동 설계

## 1. API 설정

브라우저는 빌드 시 생성되는 `config.js`에서 백엔드 주소를 읽는다.

```js
window.APP_CONFIG = {
  API_BASE_URL: "https://example-backend.onrender.com"
};
```

`API_BASE_URL`이 없으면 앱 시작 시 명확한 설정 오류를 표시하고 API 요청을 보내지 않는다. 소스 코드에 실제 Render URL을 하드코딩하지 않는다.

## 2. 공통 요청 래퍼

`api.js`의 공통 `request` 함수는 다음을 담당한다.

- 상대 경로와 `API_BASE_URL` 결합
- JSON 요청의 `Content-Type` 설정
- 성공 응답의 JSON 파싱
- `204 No Content` 처리
- 오류 응답의 `error.code`와 `error.message` 파싱
- JSON이 아닌 장애 응답의 기본 메시지 생성
- 네트워크 오류와 HTTP 오류 구분

GET 요청은 자동 재시도를 하지 않는다. POST, PUT과 DELETE는 중복 변경 가능성이 있으므로 자동 재시도를 금지한다.

## 3. 기능별 API 매핑

| 프론트 기능 | API |
|---|---|
| 초기 데이터 목록 | `GET /api/data` |
| 체중 등록 | `POST /api/data` |
| 체중 수정 | `PUT /api/data/{id}` |
| 체중 삭제 | `DELETE /api/data/{id}` |
| 요약 표시 | `GET /api/data/summary` |
| 질문 전송 | `POST /api/chat` |
| 대화 목록 | `GET /api/conversations` |
| 대화 불러오기 | `GET /api/conversations/{id}` |
| 대화 삭제 | `DELETE /api/conversations/{id}` |

`POST /api/conversations`는 백엔드 필수 API로 제공하지만 일반 채팅 흐름에서는 `/api/chat`의 자동 저장을 사용한다.

## 4. 데이터 CRUD 연동

### 등록

1. 날짜, 체중과 메모를 클라이언트에서 검증한다.
2. `POST /api/data`를 호출한다.
3. 성공하면 입력 폼을 초기화한다.
4. 데이터 목록과 요약을 병렬로 다시 조회한다.
5. 성공 알림을 표시한다.

### 수정

1. 목록 항목을 폼으로 복사하고 수정 모드로 전환한다.
2. 원래 문서 ID를 `editingDataId`에 저장한다.
3. `PUT /api/data/{editingDataId}`를 호출한다.
4. 성공하면 수정 모드를 종료하고 목록과 요약을 갱신한다.

### 삭제

1. 날짜와 체중을 포함한 확인 문구를 보여준다.
2. 확인하면 `DELETE /api/data/{id}`를 호출한다.
3. 성공하면 목록과 요약을 갱신한다.

`409 duplicate_date`는 날짜 입력 필드 근처에 표시한다. `422`는 서버의 필드 오류를 가능한 경우 해당 입력과 연결한다.

## 5. 채팅 연동

요청:

```json
{
  "message": "2025년 3월 평균 체중은?",
  "conversation_id": "현재 대화 ID 또는 null"
}
```

성공하면 `answer`를 AI 메시지로 추가하고 반환된 `conversation_id`를 현재 상태로 저장한다. 이어서 대화 목록을 갱신한다.

전송 중에는 같은 질문을 중복 제출할 수 없게 한다. 오류가 발생하면 사용자가 입력한 질문과 현재 대화 ID를 유지한다.

## 6. 대화 기록 연동

- 목록은 앱 시작과 채팅 성공 후 조회한다.
- 대화 항목 선택 시 상세 API를 호출하고 전체 메시지를 교체한다.
- 선택된 대화를 삭제하면 `currentConversationId`와 메시지를 초기화한다.
- 선택되지 않은 대화를 삭제하면 현재 채팅을 유지한다.
- 새 대화 버튼은 서버 호출 없이 로컬 상태를 초기화하고 첫 질문 시 서버가 새 ID를 생성하게 한다.

## 7. 오류별 UI 처리

| 상황 | UI 처리 |
|---|---|
| 네트워크 연결 실패 | 패널 오류 및 다시 시도 안내 |
| `400` 기간 오류 | 해당 폼 또는 채팅에 올바른 기간 요청 안내 |
| `404` | 목록을 갱신하고 이미 삭제된 기록 안내 |
| `409` 중복 날짜 | 날짜 입력에 중복 메시지 표시 |
| `422` 검증 오류 | 필드 오류 표시, 입력값 유지 |
| `502` AI 실패 | 채팅 재시도 안내, 현재 질문 유지 |
| `503` 데이터 저장소 실패 | 전역 장애 안내, 변경 성공으로 표시하지 않음 |

## 8. 요청 경합 방지

- 채팅 요청 중 전송 버튼을 비활성화한다.
- 같은 데이터 폼의 저장 요청은 한 번만 허용한다.
- 목록 새로고침이 겹치면 마지막 요청 결과만 상태에 반영한다.
- 삭제 중인 항목의 버튼만 비활성화한다.
- 대화 상세를 빠르게 바꿔 선택할 때 마지막으로 선택한 대화 결과만 렌더링한다.
