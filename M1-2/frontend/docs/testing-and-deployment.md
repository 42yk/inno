# 프론트엔드 테스트 및 배포 설계

## 1. 자동 테스트 대상

외부 프레임워크 없이 Node 기본 테스트 러너로 순수 JavaScript 함수를 검증한다.

- API URL 결합
- 체중, 변화량과 날짜 포맷
- 클라이언트 입력 검증
- API 오류 변환
- 상태 갱신 함수
- 대화 선택과 삭제 후 상태 전환

DOM 의존 기능은 작은 함수로 분리하고 핵심 상태 변환을 순수 함수로 유지한다.

## 2. 수동 기능 확인

### 초기 화면

- 데이터 목록, 요약과 대화 목록이 각각 표시된다.
- 일부 API가 실패해도 다른 패널은 사용할 수 있다.
- 빈 데이터와 빈 대화 상태가 깨지지 않는다.

### 채팅

- 새 대화에서 첫 질문을 보낸다.
- 로딩 표시 중 중복 전송이 차단된다.
- AI 답변과 새 대화 ID가 표시된다.
- 특정 날짜와 기간 통계 질문이 정확히 응답된다.
- API 실패 후 질문을 재시도할 수 있다.

### 데이터 관리

- 유효 기록을 추가한다.
- 중복 날짜와 범위 밖 체중의 오류를 확인한다.
- 날짜·체중·메모를 수정한다.
- 삭제 확인에서 취소와 확인을 각각 시험한다.
- CRUD 후 목록과 요약이 갱신된다.

### 대화 기록

- 대화 목록에서 이전 대화를 불러온다.
- 선택 상태와 전체 메시지가 표시된다.
- 선택된 대화와 다른 대화를 각각 삭제한다.
- 새 대화 버튼으로 입력 상태를 초기화한다.

### 반응형과 접근성

- 데스크톱, 태블릿과 모바일 너비에서 기능을 확인한다.
- 키보드만으로 주요 흐름을 수행한다.
- 로딩·성공·오류가 스크린 리더용 상태로 전달된다.
- 사용자와 AI 메시지가 HTML로 실행되지 않는다.

## 3. 정적 빌드

프론트는 프레임워크 없이 Node 기본 모듈만 사용하는 빌드 스크립트를 둔다.

```text
API_BASE_URL
  → scripts/build.mjs
  → src 정적 파일을 dist로 복사
  → dist/config.js 생성
```

`build.mjs`는 `API_BASE_URL`이 비어 있으면 실패한다. 로컬 개발과 Vercel 배포가 같은 생성 과정을 사용하도록 한다. 생성된 `dist`와 실제 배포 URL이 포함된 `config.js`는 Git에 커밋하지 않는다.

## 4. 로컬 실행

README에는 다음 흐름을 제공한다.

1. 백엔드를 로컬에서 실행한다.
2. `API_BASE_URL=http://localhost:8000`으로 정적 빌드를 실행한다.
3. `dist`를 정적 HTTP 서버로 제공한다.
4. 백엔드 `ALLOWED_ORIGINS`에 프론트 로컬 주소가 포함되었는지 확인한다.

HTML 파일을 파일 시스템에서 직접 열지 않고 HTTP 서버를 사용한다.

## 5. Vercel 배포

- Root Directory: `M1-2/frontend`
- Build Command: Node 정적 빌드 스크립트
- Output Directory: `dist`
- 환경 변수: `API_BASE_URL`에 Render 백엔드 주소 설정

배포 후 실제 Vercel 도메인을 백엔드 `ALLOWED_ORIGINS`에 추가하고 Render를 다시 배포한다.

## 6. 배포 확인

- Vercel URL에 접속한다.
- 브라우저 네트워크 패널에서 요청이 올바른 Render URL로 전송되는지 확인한다.
- CORS 오류가 없는지 확인한다.
- Render 콜드스타트 중 안내가 표시되는지 확인한다.
- 채팅, CRUD, 요약과 대화 불러오기를 실제 배포 환경에서 각각 실행한다.
- 브라우저 콘솔에 키, 서비스 계정이나 내부 오류가 출력되지 않는지 확인한다.

## 7. 제출 스크린샷

- 요약 패널과 질문·AI 답변이 함께 보이는 채팅 화면
- 추가·수정·삭제 중 하나의 완료 상태가 보이는 데이터 관리 화면
- 목록에서 선택한 과거 대화가 채팅 영역에 표시된 화면

스크린샷에는 Codyssey 가상 API 키, Firebase 서비스 계정, 브라우저 개발자 도구의 민감한 값이 포함되지 않게 한다.
