# UI 및 상호작용 설계

## 1. 화면 구조

데스크톱은 세 영역의 단일 페이지 대시보드로 구성한다.

```text
┌──────────────┬─────────────────────────┬──────────────────┐
│ 대화 기록    │ AI 채팅                 │ 체중 요약        │
│              │                         ├──────────────────┤
│ + 새 대화    │ 메시지 목록             │ 데이터 입력      │
│ 대화 목록    │                         ├──────────────────┤
│ 삭제         │ 질문 입력 / 전송        │ 데이터 목록      │
└──────────────┴─────────────────────────┴──────────────────┘
```

- 왼쪽 패널: 대화 기록
- 가운데 패널: AI 채팅
- 오른쪽 패널: 요약과 데이터 관리

채팅 영역을 가장 넓게 두고 좌우 패널은 독립적으로 스크롤할 수 있게 한다.

## 2. 공통 헤더

- 서비스명: 개인 체중 변화 기록 분석 AI
- 짧은 설명: 저장된 체중 기록을 조회하고 기간별 변화를 분석합니다.
- 백엔드 연결 실패 시 전역 상태 배너

로그인, 사용자 프로필, 다크 모드와 그래프는 제공하지 않는다.

## 3. 대화 기록 패널

### 구성 요소

- `새 대화` 버튼
- 최근 수정 순 대화 목록
- 각 항목의 제목과 최근 수정 시각
- 각 항목의 삭제 버튼
- 빈 상태 문구

### 동작

- 대화 항목을 누르면 전체 메시지를 불러온다.
- 현재 대화에는 시각적 선택 상태와 `aria-current`를 적용한다.
- 삭제 버튼은 대화 선택과 분리하며 삭제 전 확인한다.
- 선택 중인 대화를 삭제하면 채팅 영역을 새 대화 상태로 초기화한다.

## 4. 채팅 패널

### 메시지 목록

- 사용자 메시지는 오른쪽, AI 메시지는 왼쪽에 배치한다.
- 메시지 텍스트는 `textContent`로 렌더링해 HTML 삽입을 차단한다.
- 새 메시지가 추가되면 목록의 마지막으로 이동한다.
- 빈 상태에는 가능한 질문 예시를 표시한다.

질문 예시는 다음과 같다.

- 전체 체중 추세가 어때?
- 2025년 3월 10일 체중은?
- 2025년 3월부터 5월까지 평균 체중은?
- 가장 낮은 체중을 기록한 날짜는?

### 입력 영역

- 질문 입력 필드
- 전송 버튼
- Enter 전송, Shift+Enter 줄바꿈
- 공백 입력 차단
- 전송 중 입력과 버튼 비활성화

### 로딩과 실패

- 전송 직후 AI 로딩 버블 표시
- 요청이 오래 걸리면 Render 무료 티어의 첫 연결이 지연될 수 있다는 안내 표시
- 실패 시 로딩 버블을 제거하고 재시도 안내 표시

## 5. 체중 요약 패널

항상 다음 정보를 표시한다.

- 전체 기간
- 유효 기록 수
- 평균 체중
- 최고·최저 체중과 날짜
- 최초·최근 체중
- 전체 변화량
- 최근 10개 대비 이전 10개 추세

추세는 `증가`, `감소`, `유지`, `데이터 부족` 텍스트로 표현한다. 색상만으로 의미를 전달하지 않는다. 그래프는 구현하지 않는다.

## 6. 데이터 관리 패널

### 입력 폼

- 날짜
- 체중(kg)
- 메모
- 저장 또는 수정 완료 버튼
- 수정 취소 버튼

신규 모드와 수정 모드는 제목, 버튼 문구와 상태를 명확히 구분한다. 브라우저 검증과 별도로 서버 오류를 각 필드 또는 폼 상단에 표시한다.

### 데이터 목록

- 날짜 내림차순
- 날짜, 체중, 메모, 수정, 삭제
- 100건 이상을 표시할 수 있는 내부 스크롤 영역
- 페이지네이션과 검색은 MVP에서 제외

모바일에서는 표 대신 한 기록을 카드 형태로 재배치해 가로 스크롤을 피한다.

## 7. 반응형 규칙

- 넓은 화면: 세 열 대시보드
- 중간 화면: 대화 기록과 채팅을 먼저 배치하고 요약·데이터 관리를 아래 전체 너비에 배치
- 작은 화면: 대화 기록, 채팅, 요약, 데이터 관리 순서로 한 열 배치

모바일에서도 채팅 입력, CRUD 버튼과 대화 삭제를 사용할 수 있어야 한다. 터치 대상은 충분한 높이와 간격을 유지한다.

## 8. 접근성

- 모든 입력에 표시되는 `label` 연결
- 버튼은 아이콘만 사용하지 않고 접근 가능한 이름 제공
- 로딩 상태에 `aria-busy`
- 성공·오류 알림에 `aria-live`
- 키보드만으로 대화 선택, 전송과 CRUD 가능
- 포커스 표시 제거 금지
- 삭제 확인 후 취소하면 원래 버튼으로 포커스 복귀

## 9. 표시 형식

- 체중: `72.4kg`
- 변화량: 증가 `+0.6kg`, 감소 `-0.6kg`, 변화 없음 `0.0kg`
- 날짜: 데이터는 `YYYY-MM-DD`, 대화 시각은 사용자 로컬 형식
- 데이터 없음: `기록 없음`
- 계산 불가: `데이터 부족`
